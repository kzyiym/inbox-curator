## Inbox Curator v1.2.0

Reviews are now more focused, and the AI is held to a stricter standard for summaries and author claims.

### ✨ Highlights

- **Reading decision** — Every review opens with `Read the source` / `Summary is enough` / `Reference when needed` / `Hold` plus a one-sentence, article-specific reason. It is separate from the filing action and does not change auto-sort behavior.
- **Streamlined review output** — Overlapping sections were merged into Key Points (max 3) and Takeaways (max 2, omitted when empty). The duplicate Overview / Why It Matters / Suggested Use sections were removed.
- **Opt-in review diagnostics** — `Review current note (diagnostic capture)` records the exact system/user prompt, the raw AI response, and the normalized result to a local, git-ignored file (`.inbox-curator/diagnostics/`). It writes no review note, updates no source note, and runs no auto-sort. Secrets are masked.

### 🐛 Fixes

- Author claims are described as claims, not verified facts; unsupported usefulness/novelty is not invented.
- Subjective experience and opinion content is no longer treated as low value just for being subjective.
- Caveats are content-based; the generic "recheck the official source" boilerplate was removed.
- Notes with no readable body, or URL-only notes whose fetch failed, are skipped before the API call (no auto-sort, no API cost). Short but valid notes are still reviewed.

### 📝 Notes

- Prompt and schema cleanup: the AI no longer generates `detailedSummary`, `practicalityReview`, `retentionReasons`, `strengths`, `risksOrGaps`, `nextActions`, or `decisionReason`. Existing reviews still render via fallbacks; older reviews show the reading decision as `Not assessed`.
- The custom review prompt can now carry interests or current tasks, used mainly for the reading decision.
- `ai_review_reading_decision` is persisted to source-note frontmatter.

**Requirements:** Obsidian `1.11.4`+ (desktop only)

### 🇯🇵 Inbox Curator v1.2.0

レビュー出力をより焦点の絞られた内容に整理し、要約と著者の主張の扱いを厳格にしました。

#### ✨ 主な変更

- **読む判断（Reading decision）** — 各レビューの冒頭に `Read the source` / `Summary is enough` / `Reference when needed` / `Hold` と、記事ごとの具体的な理由を1文で表示します。整理アクションとは独立しており、自動仕分けの挙動は変わりません。
- **レビュー出力の整理** — 重複していたセクションを Key Points（最大3件）と Takeaways（最大2件・空なら省略）に統合し、Overview / Why It Matters / Suggested Use の重複を削除しました。
- **任意の診断キャプチャ** — `Review current note (diagnostic capture)` で、送信したシステム/ユーザープロンプト・生の AI 応答・正規化結果を、ローカルの git 管理外ファイル（`.inbox-curator/diagnostics/`）に記録できます。レビューノートの作成・元ノートの更新・自動仕分けは行いません。機密情報はマスクされます。

#### 🐛 修正

- 著者の主張は「検証済みの事実」ではなく「主張」として記述し、根拠のない有用性・新規性を創作しないようにしました。
- 主観的な体験・意見を、主観的であるという理由だけで低評価にしないようにしました。
- 注意書きを内容ベースにし、ソース種別だけで付いていた定型文（「公式ソースを再確認」）を削除しました。
- 本文が読めないノートや、取得に失敗した URL のみのノートは API 呼び出し前にスキップします（自動仕分けなし・API コストなし）。短くても有効なノートはレビューします。

#### 📝 補足

- プロンプト/スキーマを整理し、`detailedSummary`・`practicalityReview`・`retentionReasons`・`strengths`・`risksOrGaps`・`nextActions`・`decisionReason` の生成を廃止しました。既存レビューはフォールバックで表示され、古いレビューの読む判断は `Not assessed` と表示されます。
- カスタムレビュープロンプトに興味・現在のタスクを記載でき、主に読む判断に使われます。
- `ai_review_reading_decision` を元ノートの frontmatter に保存します。

**動作要件:** Obsidian `1.11.4`+（デスクトップ専用）
